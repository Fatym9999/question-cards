## 3. Вход

1. В приложении выбери **Регистрация**.
2. Введи почту своего аккаунта Supabase — участника команды организации проекта.
3. Придумай пароль не короче 8 символов и нажми **Создать аккаунт**.
4. Открой письмо и ссылку подтверждения. Локальный сервер должен работать.
5. После возврата при необходимости выбери **Вход** и войди.

Встроенная почта Supabase отправляет только на адреса команды и ограничена двумя
письмами в час. Для открытой регистрации с подтверждением почты нужен Custom SMTP.
Автоматические проверки писем не отправляли: реальную доставку проверяешь этим шагом.

## 4. Колоды и карточки

1. **Колоды → Новая колода → название → Создать колоду**.
2. Дату экзамена можно оставить пустой. Она хранится, но в алгоритме не участвует.
3. **+ Карточка → вопрос и ответ → Сохранить карточку**. Добавь три карточки.
4. Звёздочка справа — избранное. Текст карточки — редактирование и удаление.
5. В редакторе карточки можно выбрать другую свою колоду.
6. Кнопка **…** рядом с **+ Карточка** — редактирование/удаление колоды.
7. Обнови страницу: данные должны сохраниться в Supabase.

## 5. Повторение

1. В колоде выбери **Все / Новые / К повторению / Избранные**.
2. **Начать повторение** запускает выбранный набор этой колоды.
3. **Показать ответ** — сразу под вопросом. Три оценки доступны и до раскрытия.
4. Любая оценка после подтверждения сохранения открывает следующий вопрос без
   промежуточного экрана. Повторное нажатие на время запроса блокируется.
5. При ошибке сохранения вопрос остаётся на экране и появляется сообщение.
6. После последней карточки — **На сегодня всё**.

Вкладка **Учить** собирает все карточки с наступившим сроком из всех колод.
Участие колоды в push на обычное изучение не влияет.
**Все** включает карточки с будущим сроком; **Новые** проверяет отсутствие
`last_reviewed_at`, а не repetitions. Ответ «Не знаю» не делает карточку новой.
Оценённая карточка не возвращается немедленно в текущую сессию.

Алгоритм находится в `js/algorithm.js`:

- Не знаю: 10 минут, interval 0, repetitions 0, lapses +1.
- Сложно: max(1, round(interval × 1.3)) дней, repetitions +1, hard_count +1.
- Знаю: 3 дня с нуля, иначе round(interval × 2.5), repetitions +1.
- День — длительность 24 часа. Расписание будущих push планируется отдельно по timezone.

Интервалы в интерфейсе не показываются. В **Supabase → Table Editor → cards** после
ответа меняются поля повторения и revision; в **review_logs** добавляется одна строка.
Это один RPC и одна транзакция. При конфликте revision данные обновляются;
старый ответ не повторяется автоматически.

## 6. Настройки

**Настройки → Уведомления**: количество, окно времени, тишина и колоды сохраняются
автоматически. Главный переключатель и тестовая отправка пока недоступны.
Запроса разрешения на уведомления и push-подписки на этом этапе нет.

Пресеты: **Обычный** — 5, 09:00–20:00; **Вечер** — 3, 18:00–22:00;
**Интенсив** — 10, 09:00–21:00; **Свой** — ручные значения.
Окна могут переходить через полночь, равные границы запрещены.
Часовой пояс берётся из браузера при первом входе.

## 7. GitHub: dev → main

Локальная ветка **dev** подготовлена. Код на GitHub пока не опубликован.
После локальной проверки:

1. **GitHub → + → New repository**.
2. **Owner**: `Fatym9999`, **Repository name**: `question-cards`.
3. Для Pages на GitHub Free выбери **Public**.
4. Не добавляй README, .gitignore и лицензию здесь: локальные файлы уже есть.
5. Нажми **Create repository**.

В Terminal:

```sh
cd /Users/roman/Documents/Codex/test/question-cards
git add .
git commit -m "Добавить интерфейс карточек и повторение"
git remote add origin https://github.com/Fatym9999/question-cards.git
git push -u origin dev
```

Если Git просит имя и email автора: настрой `user.name` и `user.email` для этого
репозитория. Используй своё имя/логин и адрес GitHub либо точный приватный noreply-адрес
из **GitHub → Settings → Emails**. После этого повтори commit и оставшиеся команды.
Обычный пароль GitHub для git push не подходит; используй вход через GitHub CLI
или настроенный менеджер учётных данных Git.

Первую main создаём из проверенной dev:

```sh
git branch main dev
git push -u origin main
```

При необходимости в **Settings → General → Default branch** выбери `main`.
Локально оставайся на dev. Следующие изменения: commit/push в dev →
**Pull requests → New pull request → base: main, compare: dev → Create pull request** →
после проверки **Merge pull request → Confirm merge**.

Если репозиторий уже существует с другим содержимым, первый push отложи:
нужно сначала связать истории. `--force` не используй.
