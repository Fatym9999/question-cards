## 1. Обнови страницу

Сервер запускается прежней командой:

```sh
python3 /Users/roman/Documents/Codex/test/question-cards/scripts/serve.py
```

Если сервер уже работает, второй запуск не нужен.
Открой <http://localhost:8000/question-cards/> и обнови страницу.
Новых SQL и настроек Supabase для локального запуска нет.

## 2. Проверь на компьютере

1. Открой приложение в обычном Chrome, а не во встроенном просмотре Codex.
2. Войди → **Настройки → Установка на телефон**.
3. Если есть кнопка **Установить приложение**, нажми её и подтверди системное окно.
4. Если кнопки нет: в Chrome нажми **⋮ → Транслировать, сохранить, поделиться →
   Установить страницу как приложение**. Можно использовать значок установки справа
   от адресной строки, если он появился.
5. Открой установленную иконку. Ожидается отдельное окно «Карточки» без обычной адресной строки.
6. В этом окне **Настройки → Установка на телефон** должны показывать,
   что приложение установлено и открыто как приложение.

Браузер сам решает, когда предложить системную установку.
Отсутствие кнопки внутри страницы не доказывает, что PWA нельзя установить:
есть инструкция через меню. Safari на iPhone использует ручное добавление.

## 3. Чтобы открыть на iPhone — сначала HTTPS

`localhost` на iPhone означает сам iPhone, а не твой Mac.
Для телефона нужен опубликованный HTTPS-адрес:
`https://fatym9999.github.io/question-cards/`.

Если репозиторий ещё не создан, выполни разделы **7–8** инструкции
[этапа 2](02-frontend.md): создание question-cards, первая dev и main, GitHub Pages.
На GitHub должны попасть корневые файлы приложения, включая manifest, sw.js и папку assets/icons.

Если dev и main уже существуют:

1. Сохрани изменения в **dev**, сделай commit и push.
2. На GitHub: **Pull requests → New pull request**.
3. Выбери **base: main**, **compare: dev**, затем **Create pull request**.
4. Проверь изменения → **Merge pull request → Confirm merge**.
5. Открой **Settings → Pages**: **Source → Deploy from a branch**,
   **Branch → main**, папка **/(root)**, затем **Save**, если ещё не настроено.
6. В **Actions** дождись успешной публикации.

В **Supabase → Authentication → URL Configuration** для опубликованного сайта:

- **Site URL**: `https://fatym9999.github.io/question-cards/`.
- **Redirect URLs → Add URL**: тот же точный адрес с завершающим `/`.
- Локальный `http://localhost:8000/question-cards/` можно оставить в Redirect URLs.

Публичный адрес в этой инструкции — целевой адрес публикации, а не подтверждение,
что репозиторий уже опубликован. Текущий этап не меняет GitHub автоматически.

## 4. Установка на iPhone

1. Открой опубликованный адрес в **Safari**.
2. В приложении открой **Настройки → Установка на телефон**.
   На странице входа iPhone также есть **Как установить на iPhone**.
3. Следуй инструкции: **Поделиться → На экран «Домой» → Добавить**.
   Если Safari предлагает режим веб-приложения, оставь его включённым.
4. Закрой Safari и запусти **Карточки** с новой иконки.
5. При необходимости войди снова в тот же аккаунт.
6. Открой настройки установки: должно отображаться, что приложение уже установлено
   и открыто с иконки. Предложение установки на странице входа больше не показывается.

На iPhone будущие push требуют iOS 16.4+ и запуска установленного веб-приложения.
На этом этапе разрешение на уведомления не запрашивается.
Названия пунктов Safari могут немного отличаться в разных версиях iOS.

## 5. Android

В Chrome открой опубликованный HTTPS-адрес → **Настройки → Установка на телефон**.
Если появилась кнопка установки, используй её.
Ручной путь в актуальной справке Chrome: **⋮ → Установить и создать ярлык → Установить**.
В других версиях пункт может называться **Добавить на главный экран**.
После установки запусти иконку и проверь состояние в настройках.

## 6. Проверка для разработчика

В Chrome: **DevTools → Application**.

- **Manifest**: имя «Карточки», display `standalone`, start URL и scope
  заканчиваются на `/question-cards/`, иконки загружаются.
- **Service Workers**: worker `/question-cards/sw.js`, scope
  `http://localhost:8000/question-cards/` либо опубликованный HTTPS-адрес.
  Worker должен быть активирован. Остановка процесса worker в простое нормальна.
- **Cache Storage**: приложение не создаёт своих кешей.

Проверки:

```sh
node --test tests/algorithm.test.mjs tests/pwa.test.mjs
```

Выполнены 19 тестов: алгоритм, пути, размеры PNG, iPhone/iPadOS/standalone,
регистрация и ошибки worker, установка только по нажатию, обработчики уведомлений,
запрет открытия внешнего адреса и адреса другого приложения.
Браузерная проверка отдельно проверяет регистрацию настоящего worker в Chrome.
Проверка iPhone-интерфейса использует эмуляцию окружения, не физический iPhone.
Системную установку на своём устройстве нужно проверить вручную.

## Пути и перенос

Единственное значение base path по-прежнему находится в `js/config.js`.
Manifest лежит внутри приложения; `start_url` и `scope` равны `./` и разрешаются
от его URL. Иконки тоже относительные. При переносе это сохраняет правильный путь.
Поле id намеренно не задано: браузер берёт идентификатор из start_url,
а не присваивает приложению корень общего GitHub Pages origin.
Worker получает путь из своего зарегистрированного scope.

При смене адреса понадобится повторно установить PWA и создать push-подписку;
Auth разрешённые адреса тоже нужно обновить, как описано в этапе 1.
